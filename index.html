⠹ a workspace where coding agents live

Know which agent needs you.

Run Claude Code, Codex, Grok, OpenCode, Cursor, shells or any CLI agent side by side. trix shows you at a glance which one is working, which one is waiting on you, and which one finished while you were looking elsewhere.

alt+a

That loop runs on its own: an agent asks for permission, the strip appears, alt+a takes you straight there.

The agent comes first.

tmux and zellij don't know anything about agents. Other tools treat the agent as just another pane. trix is built around what each agent is doing.

⚓

Hooks first, guessing second

Claude Code, Codex, OpenCode and Cursor report their own lifecycle: prompts, each tool call, permission requests, finished and interrupted turns. Your agent configs are never touched.

▲

Feedback you can't miss

A red strip over your current pane, a desktop notification, a terminal bell, a rising chime when unseen work finishes, and a live title count, each one yours to switch. Each agent shows a sparkline, its branch and its diff so far.

⌥

One key to what matters

alt+a goes to the agent that has been blocked longest, then to finished work you haven't seen yet.

▦

Many agents, one glance

alt+g tiles your agents live, up to four a page, two to a row. With more, it shows the focused agent's page. Blocked tiles turn red and the rest fade back a little.

◔

Context at a glance

Each Claude and Codex pane shows how full its context window is, read from the agent's own log: context 31% · ~138k left. It turns yellow at 70% and red at 85%.

⇉

Broadcast, safely

alt+b sends one prompt to every agent, or only the idle and done ones. Agents sitting on a prompt are skipped, so a broadcast never answers a permission dialog.

⑂

Worktrees built in

Each agent can get its own trix/<name> branch in a git worktree, so parallel agents never step on each other.

⚡

Fast and quiet

Rust, alacritty_terminal and ratatui. It only redraws when something changes: about 0.4% of one core and 10 MB of RAM when idle.

◈

Follows your theme

trix reads Omarchy's colors.toml and restyles live when you switch. Without Omarchy it's Tokyo Night, or point TRIX_THEME at a colors.toml.

Bring your agent.

trix starts each agent itself and passes what it needs to that one process, so your agent configs are never touched. All five resume their conversation after a restart, and one you don't have yet installs in its own pane the first time you start it.

Not installed yet? Start it anyway.

When an agent isn't on your PATH, its pane installs it first, with the output on screen. Then the pane becomes that agent, with the first prompt, resume and hooks it would have had.

The first tool you have

mise (the packages Omarchy uses), then Homebrew, npm, or the vendor's own install script. Grok never comes from Homebrew, whose grok is another program.

⠹

Starting, not working

Install output never reads as a turn. send refuses until it's done and wait keeps waiting. Two panes starting the same agent install it once.

↻

Fails in plain sight

A failed install leaves its output on screen, and enter tries again. Log in to each agent yourself the first time it runs.

Agents can run agents.

trix spawn, send, read, wait, close and events let a script, or an agent in another pane, work the workspace the way you do. A lead Claude can start workers in their own worktrees, hand them tasks, wait for them and read what they did.

$ trix spawn claude --name api --worktree \
--prompt "add rate limiting to /login"
api ~/code/web/.trix/worktrees/api
$ trix send api "also cover it with a test"
sent to api
$ trix wait api # blocks until api stops working
api done turn finished
$ trix read api -n 80 # its last 80 lines
$ trix ls --json # state, activity, branch, diff…
$ trix close api
closed api
$ trix events api auth # follow them live (--json for scripts)

10:21:03 auth done turn finished

▲

Never answers for you

send refuses an agent that needs you, since its Enter would answer the prompt. Answering prompts is left to you on purpose.

‹

You can see who drives

Every send shows a toast, and agents another agent started or prompted show ‹lead next to their name.

⏎

Built for scripts

wait prints name state activity lines, events --json streams every change, ls --json has every detail (context included), and exit codes say what happened.

Search every agent at once.

alt+f searches every agent's scrollback as you type, newest first, grouped by agent. enter focuses that agent, scrolls to the line and selects the match.

⇢

Detach and attach

Run trix again from any terminal to pick up where you were, scrollback included. trix ls shows who needs you without attaching.

↻

Survives restarts

The workspace is saved as it changes. After a crash, a reboot or trix kill, Claude, Codex, Grok, OpenCode and Cursor resume the exact conversation each pane was in, and shells reopen in their folder.

◇

Named sessions

trix -s work and trix -s home are separate workspaces, each with its own agents, saved layout and attached terminal.

◉

Watch without taking over

trix view attaches read-only from any number of other terminals: a second monitor, a laptop over SSH, a teammate on the same box. Nothing a viewer types reaches an agent.

Your usual tabs, on demand.

A layout is a named set of tabs to open whenever you like: the three repos you always work in, a shell per service, a dev server. Opening one adds to the workspace you're in, skips tabs already open and never steals focus. Unlike restore, it stays until you remove it.

$ trix layout save work # the tabs open now
$ trix layout open work # fresh conversations
$ trix layout open work --resume # …or the saved ones
$ trix layout ls
$ trix layout rm work
# ~/.config/trix/layouts/work.toml
[[agent]]
kind = "claude"
name = "api"
cwd = "~/code/api"
args = "--model opus"
[[agent]]
kind = "shell"
name = "dev"
cwd = "~/code/web"

Plain TOML, meant to be edited by hand or by an agent. From inside a pane, an agent can open one for you too.

Make it yours.

One optional file, ~/.config/trix/config.toml, changes keys, notifications and sounds. trix reloads it within a second of each save, and trix config checks it from the command line.

# ~/.config/trix/config.toml
[keys]
new = "alt+t" # one key…
next = ["alt+j", "ctrl+down"] # …or several
jump = "ctrl+1..9"
[notify]
on = ["needs-you"] # needs-you, done
bell = false
command = "~/bin/ping-phone" # gets the event as JSON
[sound]
done = "chime" # built in, "off" or a file
needs_you = "~/sounds/knock.ogg"
mute = ["codex", "scratch"] # kinds or names

⌥

Your keys

Rebind any workspace key, or give it several. Each needs alt or ctrl, so it can't swallow what you type into agents. The footer and help show the keys you chose.

▲

Your notifications

Pick which events notify and where: the desktop, the bell, or a command of your own that gets the event as JSON. One curl to ntfy puts them on your phone.

♪

Your sounds

The built-in chime, a needs-you sound, or files of your own, each on or off. Mute an agent kind or a single agent by name.

All on alt.

Every other key goes straight to the focused agent, including shift+enter for a newline in the Claude and Codex composers. Any of these can be rebound in config.toml.

alt+nnew agent: any kind, folder, first prompt
alt+anext agent that needs you

alt+?all keys
alt+qquit (stops every agent)

Get it running.

Runs on Linux and macOS. Build it with Rust and start it with whatever agents you want.

$ git clone https://github.com/leofle/trix.git && cd trix
$ cargo install --path .
$ trix # open the workspace, or attach to the running one
$ trix claude codex shell # …and start these agents in the current folder
# (also grok, opencode, cursor; missing ones install first)
$ trix attach # attach only; fails if nothing is running
$ trix view # watch read-only from another terminal (q leaves)
$ trix ls # agents and states, without attaching
$ trix config # check ~/.config/trix/config.toml
$ trix kill # stop the workspace and every agent in it
$ trix -s work # the same, for a named session
$ trix kill --all # stop every running session
TRIX_THEME=path/to/colors.toml TRIX_NO_NOTIFY=1 TRIX_NO_SOUND=1 TRIX_CLAUDE_CONTEXT=<tokens> trix hook <source>

Using Codex? Open a Codex pane, type /hooks and trust trix's eight hooks once. From then on every Codex pane shows live detail like exec_command cargo test and apply_patch app.rs, just like Claude.

On a Mac? Every trix key is alt+…, so set your terminal's Option key to send Alt: macos-option-as-alt = true in Ghostty, Left Option as Esc+ in iTerm2, "Use Option as Meta key" in Terminal.app.
